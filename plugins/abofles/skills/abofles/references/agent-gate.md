# Agent gate

Read before the first Agent call of a session.

**Agent gate — once per session, before the first agent.** The `PreToolUse` hook denies the first Agent call of a session until you have asked it (unless the override says `Agents = auto | N | off`). Size the task first (Step 2: tier, topics, files; Small = T1–T2 one topic → 1–2 agents; Medium = T3 or two topics → 3–4; Large = T4, 3+ topics or 20+ files → 5–8 with parallel reads). Then ask **one** `AskUserQuestion` whose question text contains `Abo Fles agent gate`, options in this order, labels starting exactly like this:
1. `Auto (recommended)` — description: *abofles sizes every task by topic, side and tier (Orchestrator: Minor 2 · Normal 3 · Sensitive 7 · Critical 12 agents; Worker: 1 · 2 · 5 · 8); no more questions this session; an over-budget agent raises the budget itself (twice per task, `Budget raise = auto`).*
2. `This task: N agents` — N and the plan from your route lines, with `≈ <units> u · ≈ $<est>` (estimate $ from the session's average tokens per agent in the ledger, else 300K tokens at list price); asked again next task.
3. `Main session only` — 0 agents this task. In Orchestrator mode add *(costly: <Model> does every read itself)*.
4. Orchestrator mode, Large task only: `Max: N agents · M parallel`. Worker mode (any tier): `Switch main to Opus 5.5 and orchestrate` — if chosen, reply with one line, `Pick Opus 5.5 in the model picker (bottom right), then send "go".`, and **end the turn** (the plugin cannot switch the model).
The user may type a number, `off` or `unlimited` in Other. The hook records the answer (budget, `auto`, or `off`) and tells you `agents: …` — continue the task; never re-ask. A per-task answer expires at the receipt and the gate asks again at the next task's first agent; `Auto` and `off` hold for the session. `/abofles:agents <auto | N | off | ask>` changes it; when the user says "agents N" in chat, run `bash "<plugin root>/scripts/py" "<plugin root>/scripts/agents.py" set N --session "${CLAUDE_SESSION_ID}"`. Over an **auto** budget (the gate's `Auto`, or `Agents = auto`) with `Budget raise = auto` (the default), the hook raises the budget instead of denying: by half the tier's budget, at least 2, at most twice per task (Minor 2 → 4 → 6, Sensitive 7 → 11 → 15), and adds `abofles: budget raised N → M (auto, raise k/2)` — carry on, no question. Over a fixed budget (`Agents = N`, a `This task: N` answer), with `Budget raise = ask`, or after the second raise, the hook denies the agent: finish in the main session or ask the user to raise it (that one AskUserQuestion, within 10 min of the deny, needs no Judge) (answering the gate again — `Auto`, a number — restarts the count from that moment). Judge and Explainer agents never count, and neither does the memo agent (`abofles:abofles-memo`, started in the background only when the hook's own memo-upkeep line or `/abofles:memo` asks): no budget, no gate answer, no receipt, no main line; the receipt header names it apart (`+ 1 memo`), and the model / effort rule still applies. A prompt without the `abofles: <Topic> / <Side> · T<n>` first line has no tier: the budget is sized as 🟡 Normal and the hook says so. Background agents are capped at `Parallel` running at once (default 3).

**Sub-session cap — `Sub sessions` (default 3).** A sub session is a whole task in its own session, started with `mcp__ccd_session__start_session` (SKILL rule 12), not an agent. The cap counts the sub sessions this session started that are open: not archived in the app (`spawnedFrom.sessionId` = this session, `isArchived` false). A proposal card that was not started does not count. At the cap the hook refuses the next start and names the open ones: archive one that is done (only on the user's yes), or ask the user to raise the cap. When the app records cannot be read, the hook counts the starts it saw itself, and it never refuses on an unknown count. `Sub sessions = off` = no cap. It is apart from the two agent limits: the agent budget (`Agents`, `Agent budgets`) counts agents per task, `Parallel` counts background agents running at once, and `Sub sessions` counts open sub sessions. A sub session takes no agent budget and no `Parallel` slot here; its own agents count against its own budget, inside it, and the same gate and cap apply there.

Main-session effort lookup, last resort: the desktop `mcp__ccd_session_mgmt__get_session` tool with `"self"` (load it with ToolSearch).
